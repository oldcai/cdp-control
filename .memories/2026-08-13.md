# 2026-08-13 daemon health protocol 复盘

- 持久 daemon 的旧 health endpoint 一旦被旧 CLI exact-key 解析，就必须冻结 wire view；可演进信息应放到带稳定 `service + protocol.major/minor` 的新 endpoint。同一 major 只允许 additive optional fields，解析器的内部判别字段不能复用 wire payload 可新增的 key。
- “是同一个逻辑 daemon”与“允许向这个进程发信号”是两种 authority。前者由规范化 home + pinned endpoint 决定；后者还必须串联 health instance、PID file、唯一 listener、精确 daemon invocation 与 signal 前同步 birth identity。
- `unreachable` 只能表示确认没有 loopback listener。HTTP 在 headers/body 阶段超时可能已有占用者；在 spawn 前必须用有界 TCP connect 区分，能连接就 fail closed。
- `ready` 必须代表初始 target 枚举成功，不能由“HTTP listener 已 bind”推导。initial sync 失败要 owner-safe 撤销 PID 并关闭 listener；单个 tab 注入失败不能计入 attached，需留给后续轮询重试。
- readiness timeout 必须覆盖从 child spawn 到 ready 的真实上界（含 bind 前 process birth 读取）；不同 target 应并行 attach，等待窗口由 birth/list/connect/CDP command 的共享常量推导，避免 detached daemon 稍后成功而调用者先报假失败。
- target 并行也必须有上限；用不重叠的公平轮转批次完成首批 readiness，剩余 target 交给后续轮询，才能同时保持固定 ready 上界和避免大量 tabs 的 FD/command storm。
- 非阻塞 autostart 可以不把错误传播给主命令，但不能静默：固定 stderr 前缀并保留 `foreign` / `incompatible` / transition timeout 等具体原因。
- 本项目的测试会直接用 Node 22.6 `--experimental-strip-types` 执行 `.ts`；该版本不会正确剥离 native `#private` field 前的 TypeScript `readonly`，会留下 `readonly #field` 并在三平台 CI 报 `SyntaxError`。`#` 字段不要叠加 TS access/readonly modifier，并用锁定的 Node 22.6 真实入口验证。
